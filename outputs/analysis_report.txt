##### DEADLOCK HANDLING #####
+-----------------------+----------+------------------------------------------------------------+
| Scenario              | Outcome  | Detail                                                     |
+-----------------------+----------+------------------------------------------------------------+
| Initial state         | SAFE     | P1 -> P3 -> P4 -> P0 -> P2                                 |
| P1 requests [1, 0, 2] | GRANTED  | GRANTED: safe sequence P1 -> P3 -> P4 -> P0 -> P2          |
| P4 requests [3, 3, 0] | DENIED   | DENIED: resources not available, P4 must wait              |
| P0 requests [0, 2, 0] | DENIED   | DENIED: granting would leave the system in an UNSAFE state |
| Detection scenario    | DEADLOCK | P1, P2, P3, P4                                             |
+-----------------------+----------+------------------------------------------------------------+

Technical observations:
  - The initial state is safe, so every process can finish in the order shown.
  - A request is denied if it exceeds the claim, exceeds availability, or leads to an unsafe state.
  - Avoidance (Banker's) prevents deadlock; detection only reports it after it occurs.

Technical observations:
  - LOOK(down) gives the least head movement (208); FCFS the most (640).
  - SSTF is efficient but can starve far-away requests; SCAN/LOOK bound the wait.
  - LOOK/C-LOOK avoid travelling to the physical disk end, saving movement over SCAN/C-SCAN.
